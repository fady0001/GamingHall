# Gaming Hall — نظام إدارة صالات الألعاب

تطبيق سطح مكتب لنظام **Windows** لإدارة صالات الألعاب: تشغيل الأجهزة وحساب وقت اللعب، الفواتير، الحجوزات، قائمة المأكولات والمشروبات، المخزون والجرد، المصاريف، التقارير (مع تقرير شهري PDF)، الطباعة، والنسخ الاحتياطي. الواجهة عربية بالكامل (RTL)، وكل شيء يعمل محليًا داخل التطبيق (واجهة + منطق + قاعدة بيانات SQLite) **بدون أي سيرفر أو اتصال بالإنترنت**.

> الاسم والأيقونة عامّان عمدًا. اسم الصالة يُكتب في الإعداد الأول ويُغيَّر من الإعدادات، ويظهر على الفاتورة فقط.

## الميزات

- **الفواتير**: فاتورة لكل زبون فيها خطوط لعب ومشتريات من قائمة المأكولات والمشروبات، ومحاسبة وإغلاق.
- **الأجهزة**: بلايستيشن، كمبيوترات، طاولات (أنواعها يضيفها المدير)، وألعاب أخرى، مع حالة كل جهاز.
- **وقت اللعب**: وقت مفتوح أو محدد (مع تمديد)، تسعير يُثبَّت وقت البداية، وتنبيهات دورية.
- **الحجوزات**: مع منع التعارض وتذكير قبل الموعد بساعة.
- **المخزون والجرد**: فواتير مشتريات بالطرد أو بالقطعة، ديون الموردين، جرد يومي، وتعديل يدوي بسبب.
- **المصاريف**: صيانة، رواتب، مستلزمات صالة، مسحوبات، احتياطي، مع سجل تعديلات. مشتريات البوفيه تظهر فيها للعرض وتُحسب مع الإجمالي.
- **التقارير**: إحصائيات لأي فترة، و**تقرير شهري PDF** فيه الإيراد والمصاريف وربح التشغيل والصافي وفروقات الجرد.
- **الطباعة**: فاتورة PDF بعرض إيصال حراري 80 مم، طباعة تلقائية عند المحاسبة، وحفظ كملف.
- **النسخ الاحتياطي**: تلقائي ويدوي مع بصمة SHA-256، أرشفة شهرية، واستعادة آمنة.
- **الأمان والترخيص**: كلمة سر المدير مجزّأة بـ PBKDF2، قفل مؤقت عند التخمين، وترخيص موقَّع مقفول على جهاز واحد.
- **System Tray**: يبقى التطبيق والتنبيهات شغّالة عند إغلاق النافذة.

## التقنيات المستخدمة

| الجانب | الاختيار |
|---|---|
| الإطار / اللغة | Flutter (Windows Desktop) / Dart `^3.11.5` |
| المعمارية | Clean Architecture لكل ميزة (`domain → data → presentation`) |
| إدارة الحالة | `flutter_bloc` (Cubit) |
| قاعدة البيانات | SQLite عبر `sqflite_common_ffi` |
| الأمان والترخيص | `crypto`، `cryptography` (Ed25519) |
| الطباعة وPDF | `printing`، `pdf` |
| سطح المكتب | `window_manager`، `tray_manager`، `local_notifier`، `audioplayers`، `file_picker` |
| الخطوط | Cairo وTajawal (مضمّنة في `assets/fonts`) |

الإصدار الحالي: `1.0.0+1`.

## المتطلبات

- Flutter بإصدار يدعم Dart 3.11.5 فما فوق.
- Windows 10 أو أحدث (x64)، مع **Visual Studio** وحمل العمل "Desktop development with C++".
- إنترنت عند أول بناء: `sqflite_common_ffi` (الإصدار 2.4 فما فوق) يجلب `sqlite3.dll` تلقائيًا عبر build hooks.
- لبناء المثبّت فقط: [Inno Setup 6](https://jrsoftware.org/isinfo.php) وملف الترجمة العربية `Arabic.isl` (انظر [بناء المثبّت](#بناء-المثبّت)).

## التشغيل والبناء

```bash
flutter pub get
flutter run -d windows
```

بناء نسخة للتسليم:

```bash
flutter build windows --release
```

الناتج في `build/windows/x64/runner/Release` (انسخ المجلد كاملًا) أو ابنِ المثبّت ([بناء المثبّت](#بناء-المثبّت)). لا يوجد توليد كود (`build_runner`) في المشروع.

نافذة التطبيق تبدأ بحجم 1366×820 وأصغر حجم مسموح 360×480. تحت عرض 900 بكسل يتحول الشريط الجانبي إلى قائمة منسدلة، وتحت 600 بكسل يتحول التخطيط إلى عمود واحد.

## الاستخدام

### تدفق التشغيل

1. **فحص الترخيص**: إن لم يوجد ترخيص صالح لهذا الجهاز تظهر شاشة "التطبيق غير مُفعَّل" ([نظام الترخيص](#نظام-الترخيص)).
2. **الإعداد الأول** (مرة واحدة): اسم الصالة، اسم مستخدم المدير (3 أحرف على الأقل)، كلمة السر (6 أحرف على الأقل) وتأكيدها. لا توجد كلمة سر افتراضية. بعد الإنشاء يظهر **رمز استرداد** مرة واحدة يجب حفظه.
3. **اختيار الدور**: **موظف** (بدون كلمة سر) أو **مدير** (بكلمة السر).
4. **الشاشة الرئيسية**: الفواتير.

بعد الإعداد الأول يضيف المدير: الأجهزة وأسعارها من "الأجهزة والأسعار"، الأصناف من "قائمة المشتريات"، وبقية الخيارات من "الإعدادات".

في أسفل الشريط الجانبي: بطاقة **يوم العمل الحالي** مع زر "يوم عمل جديد"، تبديل الثيم (داكن افتراضيًا، والاختيار يُحفظ)، وتسجيل الخروج. تبديل الدور يكون بتسجيل الخروج ثم الدخول من جديد، ولا يوجد خروج تلقائي من وضع المدير بسبب الخمول.

### المصاريف (للمدير)

- تُعرض حسب الشهر (لا انتقال لشهر بعد الحالي)، مع مربعات ملخّص لكل نوع وفلاتر بالنوع.
- **الأنواع**: صيانة، رواتب، مستلزمات صالة، مسحوبات، احتياطي. الوصف إلزامي لكل الأنواع عدا المسحوبات والاحتياطي. **المسحوبات تتطلب اسم الساحب** (تُقترح الأسماء السابقة). لا يُقبل مبلغ صفر ولا تاريخ في المستقبل.
- **الحذف منطقي**: يختفي المصروف من القوائم والتقارير ويبقى أثره في تبويب **سجل التعديلات** (من فعل ماذا ومتى، مع القيم قبل وبعد).
- **مشتريات البوفيه**: لا تُضاف من هذه الصفحة. تظهر كمربع وفلتر وسطور بلا أزرار تعديل، وتُحسب ضمن "إجمالي الشهر". تُدار بالكامل من صفحة المخزون والجرد. المعروض هو **المدفوع فعليًا** حسب **تاريخ الدفع**، لا قيمة الفاتورة، وهو نفس رقم التقرير الشهري. عند اختيار فلتر مشتريات البوفيه يظهر سطر بالمبلغ **غير المسدَّد** للموردين حتى نهاية الشهر (لا يدخل في الإجمالي).

### المخزون والجرد (للمدير)

أربعة تبويبات:

- **المخزون**: الكمية الحالية وتكلفة القطعة وتحذير "منخفض/نفد" (تحذير فقط ولا يمنع البيع). لكل صنف: تعديل الكمية يدويًا (زيادة / نقص / ضبط على رقم، مع سبب إلزامي) وإعدادات الصنف (يُباع أو لا، سعر البيع، تتبّع المخزون، حدّ التنبيه).
- **المشتريات**: كل شراء **فاتورة** فيها عدة أصناف، كل سطر إما بالطرد أو بالقطعة (بسعر القطعة أو بسعر إجمالي). حقول الفاتورة (اختيارية): المورّد، رقم الفاتورة، ملاحظة، تاريخ، خصم. الدفع: كامل / غير مدفوع / جزئي، و"تسديد دفعة" لاحقًا. تعديل الفاتورة أو حذفها يعيد حساب المخزون، وتغيير تاريخ الفاتورة ينقل معها دفعتها الأولى (الدفعات اللاحقة لا تتغيّر).
- **الجرد اليومي**: إدخال الكمية الفعلية، وقبل الحفظ سؤال "هل سجّلت كل مشتريات اليوم؟". الفرق يُسوّى في المخزون.
- **سجل التعديلات**: كل تعديل يدوي مع سببه ووقته.

**الأصناف التي لا تُباع** (كاسات، مناديل...) تُضاف من شاشة الشراء بزر "صنف جديد": لا تظهر في قائمة المشتريات ولا في الفواتير لكنها تدخل المخزون والجرد. تتبّع الصنف يبدأ عند أول شراء أو جرد أو تعديل له، فلا تُخصم المبيعات القديمة.

### التقارير (للمدير)

- أرقام الإحصائيات من **الفواتير المغلقة فقط**. الفترة: يوم العمل الحالي / هذا الأسبوع (يبدأ من السبت) / هذا الشهر / **فترة مخصصة** (روزنامة منبثقة: يوم البداية ثم النهاية، والأيام بعد اليوم معطّلة).
- المحتوى: المبيعات (الإجمالي، متوسط الفاتورة، أعلى فاتورة)، مصادر الدخل، إيراد اللعب حسب النوع، نشاط الصالة (جلسات، ساعات، متوسط المدة، ساعة الذروة، الحجوزات)، الأيام (متوسط، أفضل، أضعف) عند فترة أكثر من يوم، والأفضل أداءً (الأكثر ربحًا ولعبًا وحجزًا والصنف الأكثر مبيعًا).
- **التقرير الشهري PDF** (زر "تقرير شهري PDF"): تختار الشهر فيُحفظ ويُفتح تلقائيًا في `المستندات\GamingHall\Reports\monthly-report-<سنة>-<شهر>.pdf`، وإعادة إنشاء نفس الشهر تستبدل الملف. يحتوي: الإيراد، المصاريف، ربح التشغيل، المسحوبات والاحتياطي والصافي، رصيد الاحتياطي التراكمي، المشتريات غير المسدّدة، أكثر الأصناف مبيعًا، وفروقات الجرد.

### الإعدادات

بيانات الصالة والفاتورة (الاسم، الهاتف، عبارة أسفل الفاتورة)، التسعير (أقل مبلغ للفاتورة والتقريب)، التنبيهات، الطباعة، الأمان (اسم المدير وتغيير كلمة السر)، النسخ الاحتياطي، وحول التطبيق (الإصدار و**كود هذا الجهاز**). لا بدّ من "حفظ الإعدادات" ليسري التغيير. قسم **أدوات التجربة** (بيانات تجريبية لآخر 10 أيام تُضاف وتُحذف دون المساس بالبيانات الحقيقية) يظهر في نسخة **Debug فقط**.

### الطباعة وحفظ الفاتورة

الفاتورة PDF بعرض إيصال حراري 80 مم، وتحمل اسم الصالة والهاتف والعبارة الأخيرة (الافتراضي "شكرًا لزيارتكم"). من الإعدادات ← الطباعة: اختيار الطابعة (أو الافتراضية في ويندوز)، وتفعيل **الطباعة التلقائية عند المحاسبة**. إن فشلت الطباعة تظهر رسالة بالسبب والفاتورة تبقى مغلقة سليمة. من الفاتورة المغلقة: طباعة، معاينة، أو حفظ PDF في `المستندات\GamingHall\Invoices`.

### System Tray والإغلاق

زر الإغلاق (X) **يخفي النافذة فقط** ويبقى التطبيق والتنبيهات شغّالين. أيقونة الـ tray: نقرة تُظهر النافذة، وقائمة الزر الأيمن فيها "إظهار التطبيق" و"إغلاق التطبيق نهائيًا" (بتأكيد، مع تحذير إن كان هناك لعب جارٍ: الوقت يستمر بالعدّ لكن التنبيهات تتوقف). إن تعذّر إنشاء أيقونة الـ tray فلا تُخفى النافذة أبدًا.

## قواعد العمل

**الفواتير**
- الكمية في الفاتورة حتى 999، وتخفيضها إلى صفر يحذف السطر. اسم الزبون حتى 60 حرفًا.
- "محاسبة وإغلاق" تطلب تأكيدًا، والفاتورة الفارغة لا تُحاسَب، والفاتورة المغلقة للقراءة فقط. حذف الفاتورة للفارغة فقط.
- لا يوجد: إلغاء فاتورة، خصم، نقل لاعب بين الأجهزة، إيقاف مؤقت، دفع جزئي.
- **يوم العمل الجديد** يُرفض إن وُجدت فواتير مفتوحة، ولا يحاسب أحدًا تلقائيًا؛ عند قبوله يُغلق اليوم الحالي ويُحفظ في السجل.

**التسعير والحساب**
- السعر يُثبَّت على خط اللعب وقت بدايته. **البلايستيشن فقط** له سعر لكل عدد لاعبين (1 إلى 4)، وغيره له سعر ساعة واحد.
- الوقت لأقرب دقيقة (30 ثانية فأكثر = دقيقة)، والأجر = سعر الساعة × الدقائق ÷ 60 مقرَّبًا لأقرب ليرة.
- **الحد الأدنى للفاتورة** 5,000 ل.س افتراضيًا (قابل للتعديل، و0 يلغيه). **التقريب**: بدون، أو لأقرب 100 أو 500 أو 1,000. الترتيب: المجموع ← الحد الأدنى ← التقريب، ولا ينزل الناتج تحت الحد الأدنى. العملة: ل.س.

**أنواع الوقت**
- **مفتوح**: يوقفه الموظف بزر "إيقاف" ويشمله التذكير الدوري.
- **محدد** (من دقيقة إلى 24 ساعة): ينتهي تلقائيًا بالضبط حتى لو كان التطبيق مخفيًا، مع صوت وإشعار ويندوز وزر "تمديد 15 دقيقة". إن غادر الزبون قبل الانتهاء يُحاسَب بدقائقه الفعلية. **التمديد** قبل الانتهاء يزيد مدة نفس الخط، وبعده يفتح خطًا جديدًا من لحظة التمديد؛ ومجموع الوقت لا يتجاوز 24 ساعة ولا يُسمح به إن تعارض مع حجز.
- قيد في قاعدة البيانات يمنع تشغيل جهاز واحد في لعبين جاريين معًا.

**التنبيهات**: تذكير باللعب **المفتوح** الجاري كل ربع ساعة أو نصف ساعة أو ساعة أو إيقاف (القيم 15 / 30 / 60 / 0). كل تنبيه: نغمة وإشعار ويندوز وبطاقة أعلى الشاشة فيها "فتح الفاتورة". لا يوقف اللعب ولا يغيّر الحساب. يفحص التطبيق كل 5 ثوانٍ ويعمل والنافذة مخفية.

**حالات الجهاز**: متاحة / مشغولة / محجوزة (له حجز خلال الساعة القادمة) / خارج الخدمة (يضبطها المدير).

**الحجوزات**
- الحقول: اسم الزبون، **هاتف إلزامي** (10 أرقام ويبدأ بـ 09)، الجهاز، عدد اللاعبين، التاريخ، وقت البداية، نوع الوقت (محدد أو مفتوح).
- لا حجز في وقت مضى ولا حجز يتعارض مع حجز محدد آخر على نفس الجهاز (المتلاصقان لا يتعارضان). الحجز **المفتوح** لا يحجز الجهاز فعليًا.
- قبل الموعد بساعة: يظهر الجهاز "محجوزة" وتذكير واحد فيه "بدء اللعب الآن".
- بدء لعب أو تمديد يتداخل مع حجز قريب يُرفض برسالة توضّح أقصى مدة ممكنة. حالات الحجز: قادم / تم تحويله إلى فاتورة / ملغي.

**الأجهزة والأسعار**: أقسام بلايستيشن وكمبيوتر وطاولات وألعاب أخرى. أنواع الطاولات يضيفها المدير مرة واحدة (حذف النوع مرفوض إن استعملته طاولة). أسماء الأجهزة فريدة دون اعتبار حالة الأحرف، وحذف الجهاز لا يمسّ فواتير سابقة.

**قائمة المشتريات**: الفئات مأكولات، مشروبات باردة، مشروبات ساخنة، أراكيل، أخرى. الأسماء فريدة، والتعديل متاح للموظف والمدير.

## النسخ الاحتياطي والأرشفة

قاعدة البيانات ملف SQLite واحد، والنسخة نسخة كاملة منه.

- **طريقة النسخ**: `VACUUM INTO` (نسخة متسقة والتطبيق شغّال)، باسم `gaming_hall_backup_<التاريخ-الوقت>.db` وبجانبها بصمة `.sha256` تُفحص قبل الاستعادة.
- **تلقائيًا**: عند التشغيل ثم فحص كل 30 دقيقة؛ إن مرّت 24 ساعة على آخر نسخة تؤخذ نسخة جديدة. يُحتفظ بآخر **30** نسخة (يُحذف الأقدم مع بصمته، ويشمل العدّ أي نسخة بنفس الاسم حتى اليدوية). يعمل والتطبيق شغّال، ومنه وهو مخفي في الـ tray.
- **المكان الافتراضي**: `المستندات\GamingHall\Backups`، ويمكن تغييره (يُفضَّل فلاشة أو قرص آخر). إن صار المجلد غير متاح يُستخدم الافتراضي تلك المرة.
- **الأزرار** (الإعدادات ← النسخ الاحتياطي): نسخة احتياطية الآن، تغيير مجلد النسخ التلقائي، نسخ إلى مجلد أو فلاشة (مرة واحدة)، أرشفة الآن، استعادة من نسخة.
- **الأرشفة**: نسخة كاملة تُحفظ كل شهر ولا تُحذف تلقائيًا أبدًا، في `<مجلد النسخ>\Archive\GamingHall_archive_<سنة>-<شهر>-<يوم>.db` مع `.sha256`. العدّاد يبدأ أول مرة يعمل فيها التطبيق، والفاصل الثابت `archiveEveryMonths = 1` في `lib/core/backup/backup_service.dart`.

**الاستعادة**: تأكيد (تُستبدل كل البيانات الحالية) ← اختيار ملف `.db` ← فحص البصمة ثم `integrity_check` والتأكد من جداول التطبيق ← إيقاف النسخ التلقائي وإغلاق القاعدة ← حفظ نسخة أمان بجانب القاعدة باسم `gaming_hall.db.before_restore` (واحدة فقط، تُكتب فوقها كل مرة) ← استبدال القاعدة ثم يطلب التطبيق إعادة تشغيله.

ملاحظات:
- مجلد النسخ التلقائي وتاريخ آخر أرشفة مخزّنان داخل القاعدة نفسها، فاستعادة نسخة قديمة تعيد إعداداتها القديمة.
- النسخ غير مشفّرة وتحوي بيانات الفواتير وتجزئة كلمة سر المدير، فلا تُترك الفلاشة في مكان مكشوف.
- البصمة تكشف التلف لا التلاعب.

**مكان قاعدة البيانات**: مجلد `Application Support` للتطبيق، الملف `gaming_hall.db` (يُنقل تلقائيًا إن وُجد ملف قديم باسم `game_lounge.db`).

## الأمان

- كلمة سر المدير مخزّنة بـ **PBKDF2-HMAC-SHA256** مع ملح عشوائي 16 بايت: **600,000 تكرار** على ويندوز (المحرّك الأصلي)، أو 300,000 إن تعذّر. التجزئات القديمة (100,000) تُقبل وتُرقّى تلقائيًا عند أول دخول ناجح. لا يوجد أي اسم مستخدم أو كلمة سر داخل الكود.
- **قفل مؤقت**: بعد 5 محاولات خاطئة يُقفل الدخول دقيقة، ثم مع كل محاولة خاطئة: 2 ثم 4 ثم 8 ثم 15 دقيقة (الحد الأقصى). العدّاد يشمل خطأ رمز الاسترداد ويُصفَّر عند النجاح.
- **نسيان كلمة السر**: "نسيت كلمة السر؟" في نافذة دخول المدير ← رمز الاسترداد ثم كلمة سر جديدة (6 أحرف على الأقل). بعد النجاح يصدر **رمز استرداد جديد** يُعرض مرة واحدة ويبطل القديم.
- **حماية حساب المدير**: علامة `.manager_registered` تُكتب في مكانين خارج مجلد القاعدة (`المستندات\GamingHall` و`%LOCALAPPDATA%\GamingHall`). إن اختفت القاعدة وبقيت العلامة يرفض التطبيق إنشاء حساب مدير جديد ويعرض شاشة "تعذّر العثور على بيانات التطبيق" لاستعادة نسخة احتياطية.
- صلاحية المصاريف تُفحص في الـ Cubit وليس في الواجهة فقط، وكل عمليات الكتابة داخل معاملات SQLite.

## نظام الترخيص

التطبيق مقفول على **جهاز واحد** بترخيص موقَّع بخوارزمية **Ed25519**: يحمل التطبيق **المفتاح العام فقط** (`lib/core/security/license_public_key.dart`)، والمفتاح الخاص يبقى عند المطوّر.

- **كود الجهاز** بصيغة `XXXXXXXX-XXXXXXXX-XXXXXXXX-XXXXXXXX`، مشتق من `MachineGuid` الخاص بويندوز (وإلا من UUID النظام)، لا من عنوان MAC. إعادة تثبيت ويندوز تغيّر الكود. يظهر في شاشة التفعيل وفي الإعدادات ← حول التطبيق.
- **ملف الترخيص** `license.lic` يوضع في مجلد `Application Support` للتطبيق أو يُختار من شاشة التفعيل. يُرفض إن كان مفقودًا أو تالفًا أو بتوقيع غير صالح أو لكود جهاز مختلف.

**قبل أول عميل**: تأكد أن المفتاح العام في المشروع هو مفتاحك، وإلا ولّد زوجًا جديدًا:

```bash
dart run tool/license_tool.dart keygen
```

يُنشئ `license_private_key.txt` (احفظه بعيدًا عن المشروع ولا ترفعه إلى GitHub ولا تشاركه) ويطبع المفتاح العام لتضعه في `license_public_key.dart` ثم تعيد البناء.

لكل عميل:

```bash
dart run tool/license_tool.dart sign <كود_الجهاز> <مسار_license_private_key.txt>
```

ينتج `license.lic` في المجلد الحالي ليُرسَل للعميل. لا تعطِ العميل مجلد `tool` ولا المفتاح الخاص، فقط ملف المثبّت.

لمعرفة كود الجهاز دون تثبيت التطبيق: `tool/GetDeviceCode.bat` (مع `Get-DeviceCode.ps1`). تحقق أنه يطابق الكود الظاهر في شاشة التفعيل قبل الاعتماد عليه.

## بناء المثبّت

1. `flutter build windows --release`
2. افتح `installer/gaming_hall_setup.iss` في Inno Setup واضغط Compile (Ctrl+F9). السكربت يستخدم `Arabic.isl` من مجلد Inno Setup إن وُجد، وإلا يجب وضعه بجانب السكربت في `installer/` (الملف غير مرفق في المستودع).
3. الناتج: `build/installer/GamingHall-Setup-1.0.0.exe`

المثبّت للأنظمة x64، يثبّت في `Program Files\GamingHall`، وينشئ اختصارًا في قائمة البرامج (وعلى سطح المكتب إن اختير) بواجهة عربية. معرّف `AppId` داخل السكربت لا يُغيَّر بعد أول نسخة تُباع. عند تغيير رقم الإصدار حدّثه في `pubspec.yaml` و`lib/core/constants/app_info.dart` و`installer/gaming_hall_setup.iss`.
